# AI-use disclosure (assignment §5.3)

## Summary paragraph

AI tools wrote most of SilverFile's code and documentation, and the team directed, reviewed, tested and integrated that work. Claude Code first generated the application (agents, LangGraph graph, service layer, MCP tax tools, Streamlit UI, PDF output and the original tests) in the team's earlier repository, recorded under "Inherited source" below. ChatGPT/Codex then split that code into six packages, one per member, and while packaging it adapted the code (for example, unreadable amounts stay unknown instead of zero, 1099-R box 2b escalates before deduplication, the wage tolerance became zero, and multi-page PDFs are rejected), regenerated the fictional fixtures, assembled the reference-form corpus and its hash manifests, and wrote regression tests and handoff notes. Members then used Claude Code (Claude Opus 5.5 and Claude Sonnet 5.5), Cursor and ChatGPT/Codex for the later work: importing and committing the packages, the acceptance fixes and audit recheck, native OCR for keyless W-2 reading, W-2 box 6 and the line 25c tool, the rules defect fixes and work plan, the context-benchmark harness and the formatting of its report, the documentation, the five-page report, and running tests. The table below lists each stage, the tool used and what it produced; commit trailers name the co-authoring tool where one was recorded. Each member reviewed the changes in their area and the team tested the integrated system, as recorded in [CONTRIBUTIONS.md](CONTRIBUTIONS.md) and [ACCEPTANCE_RESULTS.md](ACCEPTANCE_RESULTS.md). At run time, SilverFile itself calls Anthropic Claude models for W-2 vision extraction, interpretation of intake replies, an advisory audit critique and plain-language line explanations, but every dollar amount on the return comes from a deterministic MCP tool, never from a model.

The hash and identity checks show file identity, not that the forms are official or that the citations are interpreted correctly.
